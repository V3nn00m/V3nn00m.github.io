<p>
We see two tables here: the first table (<code style="color: chartreuse;">$LN10@f</code>) is an index table, and the second (<code style="color: chartreuse;">$LN11@f</code>) is an array of pointers to blocks.
</p>
<p>
First, the input value is used as an index in the index table (line 13).
</p>
<p>
Here is a brief explanation of the table values:
</p>
<ul>
  <li>0 is the first case block (for values 1, 2, 7, 10)</li>
  <li>1 is the second (for values 3, 4, 5)</li>
  <li>2 is the third (for values 8, 9, 21)</li>
  <li>3 is the fourth (for value 22)</li>
  <li>4 is for the default block</li>
</ul>
<p>
Here we get an index for the second table that contains pointers to code and jump there (line 14). It is also noteworthy that there is no case for input value 0. Therefore, we see a <code style="color: chartreuse;">DEC</code> instruction at line 10, and the table starts at a = 1, so there is no need to reserve a table element for a = 0. This is a very popular pattern.
</p>
<p>
Why is this economical? Why not do it like before with just one table of pointers to blocks?
</p>
<p>
The reason is that the elements of the index table are 8-bit, so all this is smaller and more compact.
</p>

<h3 style="color: crimson; font-family: 'Press Start 2P', 'system-ui'">GCC</h3>

<p>
GCC does the same thing in the way we discussed before, using just one table of pointers.
</p>

<h3 style="color: crimson; font-family: 'Press Start 2P', 'system-ui'">ARM64: Optimizing GCC 4.9.1</h3>

<p>
No code will be executed if the input value is 0, so GCC tries to make the jump table smaller by starting from input value 1. GCC 4.9.1 for ARM64 uses an even smarter trick.
</p>
<p>
It is able to encode all offsets as 8-bit bytes. Recall that all ARM64 instructions are 4 bytes in size. GCC exploits that all offsets in this small example are close to each other. Thus the jump table consists of single bytes.
</p>

So for case 1, the value 9 will be multiplied by 4 and added to the address of label <code style="color: chartreuse;">Lrtx4</code>. For case 22, the value 0 will be multiplied by 4, resulting in 0. Immediately after label <code style="color: chartreuse;">Lrtx4</code> is label <code style="color: chartreuse;">L7</code>, where the code that prints "22" is located.
</p>
<p>
There is no jump table in the code section; it is placed in a separate read-only data (<code style="color: chartreuse;">.rodata</code>) section (there is no special need for it to be in the code section). There are also negative bytes (0xF7), which are used to go back and jump to the code that prints the "default" string (at <code style="color: chartreuse;">.L2</code>).
</p>

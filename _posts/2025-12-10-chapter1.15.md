<h1 style="color:#9a3ba6;"><b>1.15 More about results returning</b></h1>
<img src="/assets/img/resultsreturning.png" alt="resultsreturning" style="display:block; margin:20px auto; border-radius:12px; max-width:80%;">
<p>
The author said that in x86, the result of function execution is usually returned in the <code style="color: chartreuse;"> EAX </code> register. If the type is <b style = "color: cornflowerblue;">byte</b> or <b style = "color: cornflowerblue;">char</b>, the lower part of the <code style="color: chartreuse;"> EAX </code> register which is <code style="color: chartreuse;">AL</code> is used. If the function returns a <b style = "color: cornflowerblue;">float</b> number, the <code style="color: chartreuse;">FPU register ST(0)</code> is used. In ARM, the result is usually returned in the<code style="color: chartreuse;"> R0</code> register.
</p>

<p>
If you wrote <code style="color: chartreuse;">void main()</code> instead of <code style="color: chartreuse;">int main()</code>, what happens?
</p>
<ul>
<li><code style="color: chartreuse;">void main()</code> means that no value is expected to be returned explicitly. But the <code style="color: chartreuse;">EAX</code> register may contain any meaningless value (leftover) from previous instructions.</li>
<li>When the <b style = "color: cornflowerblue;">startup code</b> does <code style="color: chartreuse;">push eax</code> after <code style="color: chartreuse;">call main</code>, it will send the value in <code style="color: chartreuse;">EAX</code> to <code style="color: chartreuse;">exit()</code> — and therefore the exit code will be a random value or a value from the last executed function (like <code style="color: chartreuse;">puts()</code> or <code style="color: chartreuse;">printf()</code> if used).</li>
</ul>

<h2 style="color:#3ba2a6;"><b>1.15.3 Returning a structure</b></h2>
<img src="/assets/img/Returningastructure.png" alt="Returningastructure" style="display:block; margin:20px auto; border-radius:12px; max-width:80%;">

<p>
The author then explained and said the truth is that the return value is computed in the EAX register.
</p>
<p>
And without much chatter, the reason is that old C compilers could not make a function return something that does not fit in one register (usually int)
</p>
<p>
If one needs to return something bigger, he must return the data through pointers sent as arguments to the function.
</p>
<p>
So it is very normal that a function returns one value only, and the rest returns it through pointers.
</p>
<p>
Now we can return a full struct, but the subject is not famous.
</p>
<p>
If a function must return a large struct, the function that calls it (the caller) must allocate it and send a pointer to it as the first argument, and this happens hidden from the programmer.
</p>
<p>
Meaning it is the same idea as if you send a pointer in the first argument by hand, but the compiler hides this.
</p>
<p>
A small example:
</p>

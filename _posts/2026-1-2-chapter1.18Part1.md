<p>
We will talk first about the first instruction which is <code style = "color: chartreuse;">JLE</code> and this means <b style = "color: cornflowerblue;">(Jump if Less or Equal)</b>
</p>
<p>
Meaning if the operand if the second operand is greater than or equal to the first, the execution will jump to the address or the label that is in the instruction. If this condition is not met <b style = "color: cornflowerblue;">(meaning the second operand is smaller than the first)</b>, the execution will not change, and the first <code style = "color: chartreuse;">printf()</code> will be executed
</p>
<p>
The second check is <code style = "color: chartreuse;">JNE : Jump if Not Equal</code>.
</p>
<p>
<b style = "color: cornflowerblue;">Meaning the execution will not jump if the two values are equal.</b>
</p>
<p>
The third check is <code style = "color: chartreuse;">JGE : Jump if Greater or Equal</code>
</p>
<p>
<b style = "color: cornflowerblue;">Meaning jump if the first operand is greater than the second or equal to it.</b>
</p>
<p>
So if these three conditional jumps are met,
</p>
<p>
Not a single <code style = "color: chartreuse;">printf()</code> will be executed at all.
</p>
<p>
And this is impossible to happen without special intervention.
</p>
<p>
And because this part confused me a bit too I will explain it to you one by one simply 
</p>
<p>
The compiler does not write the same condition as in C it does the opposite
</p>
<p>
Meaning for example when we come to the first condition which was <code style = "color: chartreuse;">if (a > b)</code> then the compiler if the condition is not a>b jump and pass normally
</p>
<p>
And here the sentence <b style = "color: cornflowerblue;">“not a>b”</b> will mean <b style = "color: cornflowerblue;">a<=b</b>
</p>
<p>
That's why it was in Assembly <code style = "color: chartreuse;">JLE ; Jump if Less or Equal</code> and so on for the rest
</p>

<p>
As said before, the jump instructions here are different:
</p>
<p>
* <b style = "color: #af9c0b">JBE = Jump if Below or Equal</b>
</p>
<p>
* <b style = "color: #af9c0b">JAE = Jump if Above or Equal</b>
</p>
<p>
These instructions <code style = "color: chartreuse;">(JA / JAE / JB / JBE)</code> differ from
</p>
<p>
<code style = "color: chartreuse;">(JG / JGE / JL / JLE)</code>
</p>
<p>
In that they work with unsigned numbers.
</p>
<p>
And therefore, if we see:
</p>
<p>
* <b style = "color: #af9c0b">JG / JL used → probably the variables are signed</b>
</p>
<p>
* <b style = "color: #af9c0b">JA / JB used → probably the variables are unsigned</b>
</p>

<p>
The author said that many instructions in ARM Mode can be executed only if certain flags are set1
</p>
<p>
This style is used a lot in number comparison.
</p>
<p>
For example, the <code style = "color: chartreuse;">ADD</code> instruction its real name internally is <code style = "color: chartreuse;">ADDAL</code> and the AL means Always meaning execute always the predicates are encoded in the top 4 bits of the 32-bit ARM instruction (condition field).
</p>
<p>
Even the B instruction (unconditional jump) is in fact a conditional instruction, encoded like any other conditional jump,
</p>
<p>
But its condition is <code style = "color: chartreuse;">AL</code>, meaning execute always regardless of the flags.
</p>
<p>
The ADRGT instruction works exactly like <code style = "color: chartreuse;">ADR</code>, but is executed only if the CMP instruction before it found that the number is greater than the other (Greater Than).
</p>
<p>
Meaning ADRGT puts a pointer to the string "a>b\n" in register R0 while BLGT calls <code style = "color: chartreuse;">printf()</code>
</p>
<p>
Thus any instruction ending with GT- is executed only if the value in R0 (which is a) is greater than the value in R4
</p>
<p>
(which is b )
</p>
<p>
After that we see <code style = "color: chartreuse;">ADREQ</code> and <code style = "color: chartreuse;">BLEQ</code> instructions.
</p>
<p>
These work like <code style = "color: chartreuse;">ADR</code> and <code style = "color: chartreuse;">BL</code>,
</p>
<p>
But are executed only if the two values were equal in the last comparison.
</p>
<p>
That's why there is another CMP before them,
</p>
<p>
Because calling <code style = "color: chartreuse;">printf()</code> may have messed with the flags.
</p>
<p>
After that we see the <code style = "color: chartreuse;">LDMGEFD</code> instruction.
</p>
<p>
This instruction works like <code style = "color: chartreuse;">LDMFD</code>,
</p>
<p>
But is executed only when one of the values is greater or equal to the other (Greater or Equal).
</p>
<p>
The instruction:
</p>
<p>
<code style = "color: chartreuse;">LDMGEFD SP!, {R4-R6,PC}</code>
</p>
<p>
This is considered function epilogue,
</p>
<p>
But it will be executed only if a >= b,
</p>
<p>

</p>
<p>

</p>
<p>

</p>

</p>
<p>

<p>
MIPS
</p>
<p>
The author mentioned that one of the distinctive things in MIPS is that there are no flags. Apparently this is done to simplify data dependency analysis.
</p>
<p>
There are instructions similar to SETcc in x86: there is SLT (“Set on Less Than”: the signed version) and SLTU (the unsigned version).
</p>
<p>
These instructions put the value 1 in the destination register if the condition is met, or 0 if not.
</p>
<p>
After that the destination register is checked using BEQ (“Branch on Equal”) or BNE (“Branch on Not Equal”) and a jump may occur.
</p>
<p>
Meaning, this pair of instructions must be used in MIPS for comparison and branching.
</p>

<p>
We saw a new instruction: BLTZ (“branch if less than zero”).
</p>
<p>
Also there is pseudo instruction NEGU, which simply subtracts from zero.
</p>
<p>
The “U” suffix in SUBU and NEGU means no exception will be raised if integer Overflow occurs.
